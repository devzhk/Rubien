## Release procedure

1. Synchronize main, bump VERSION/BUILD.txt, regenerate the CLI version, and
   commit and push release preparation.
2. Require green CI for that exact preparation SHA, then validate live CloudKit
   Development and Production against the checked-in schema.
3. Build the unsigned release candidate and verify SDK/deployment metadata,
   architectures, dSYMs, DMG size/integrity, and matching extension packages.
4. Present the exact version/build, notes, CI and CloudKit results, and release
   command for explicit approval under Docs/Release-Runbook.md.
5. After approval, sign/notarize/publish through scripts/release.sh. Verify the
   public Mac release, Sparkle feed, source tag, and Linux workflow/assets; retain
   debug symbols in the existing durable private archive.

Comparison with v0.8.6 shows no browser extension, native host, shared browser
protocol/import, registration, or packaging changes. Skip the human Chrome
smoke gate and Web Store submission per the runbook; still publish the matching
manual extension ZIP. There are no mcp-server changes or npm publication.
