Base: public main at 644e2c5d. Keep attachment iCloud sync opt-in.

1. Integrate attachment, reader, layout, and storage fixes in a clean release checkout.
   Preserve unrelated website work in the original checkout.
2. Confirm the review choice required by AGENTS.md; build and test release changes.
3. Commit and push preparation to main; require green CI for that exact revision.
4. Validate live CloudKit Development and Production against the checked-in schema.
5. Build unsigned candidate app and extension packages for the user-run import checks.

## Proposed release notes

- Add multiple PDF and Markdown attachments to references, including drag-and-drop import.
- Read attachments with annotations and the Assistant sidebar; reveal, open, and remove files from reference details.
- Print papers and Markdown documents from their readers with Command-P or Control-P.
- Improve sidebar hit targets, toolbar placement, and the Home reading activity panel.
- Add attachment commands and tools to the CLI and MCP server; improve library startup and recovery errors.
- Attachment iCloud sync is experimental and remains disabled by default.

## CloudKit deployment completed

Read-only exports confirm that Development and Production have identical existing
record definitions, matching the checked-in schema. Both lack exactly these types:

- `CDReferenceAttachment`: file metadata and parent identity.
- `CDAttachmentAsset`: attachment bytes and content identity.
- `CDAttachmentAnnotation`: attachment annotations and anchors.

The approved deployment added only those three definitions from
`CloudKit/RubienSchema.ckdb`; it changes no existing type, field, index, or grant.
CloudKit Console confirmed “Changes Deployed,” and
`scripts/validate-cloudkit-schema.sh` passed for both live environments.
Production additions are permanent. Schema deployment does not move or delete data
and does not enable attachment sync in the app.
